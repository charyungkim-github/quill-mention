# Quill-Mention 커스텀 프로젝트 규칙

이 문서는 quill-mention 라이브러리 v6.1.1을 fork하여 한글 입력 문제를 해결하는 프로젝트의 개발 규칙을 설명합니다.

---

## 🎯 프로젝트 목표

**해결할 문제**: 한글 멘션 검색이 실시간으로 작동하지 않습니다.

**현상**:

- `@가` 입력 시 "가"로 검색된 멘션 리스트가 즉시 나타나지 않음
- 이전 멘션 리스트가 그대로 유지됨
- 마우스로 다른 곳을 클릭해야 "가"로 검색된 리스트가 표시됨

**원인**: 한글 입력 중(IME composition 상태)에 renderList는 호출되지만 DOM이 즉시 반영되지 않는 문제

**목표**: `@가` 입력 시 즉시 "가"로 시작하는 멘션 리스트가 표시되어야 하며, 기존 기능은 모두 정상 작동해야 합니다.

### 3단계: 실제 테스트

### 4단계: 전체 기능 검증

아래 체크리스트의 모든 항목을 테스트하여 기존 기능이 깨지지 않았는지 확인합니다.

## ✅ 필수 테스트 체크리스트

코드 수정 후 반드시 모든 항목을 테스트해야 합니다:

1. **기본 표시**: `@` 입력 시 모든 멘션 리스트가 나타나는가?
2. **영문 검색**: `@영문` 입력 시 검색이 되는가?
3. **한글 검색**: `@한글` 입력 시 검색이 되는가?
4. **키보드 네비게이션**: 화살표 키를 처음 눌렀을 때 UI에 이상이 없는가?
5. **문장 중간 멘션**: "테스트문장" 입력 후 커서를 중간으로 이동하여 `@멘션`을 입력했을 때 정상 작동하는가?
6. **여러 줄 중간 멘션**:
   ```
   테스트문장 첫번째 줄
   테스트문장 두번째 줄
   ```
   첫 번째 줄 끝에서 `@멘션`을 입력했을 때 정상 작동하는가?
7. **화살표 선택**: `@멘션` 검색 후 화살표 키로 항목 선택이 가능한가?
8. **엔터 입력**: `@멘션` 선택 후 엔터를 눌렀을 때 올바르게 입력되는가?
9. **ESC 닫기**: `@멘션` 검색 후 ESC로 리스트가 닫히는가?
10. **ESC 채팅방 닫기**: 멘션 리스트가 없을 때 ESC로 채팅방이 잘 닫히는가?
11. **한글 UI 안정성**: `@한글` 검색 및 선택 시 flickering, position 문제가 없는가?
12. **연속 한글 검색**: `@한글 @한글` 두 번 연속 검색 시 문제가 없는가?

## 💻 코드 작성 규칙

### 주석 규칙

모든 커스텀 코드(새로운 변수, 함수, 로직)에는 `// Rfice ::` prefix를 붙입니다.

**예시**:

```typescript
// Rfice :: 한글 실시간 검색을 위한 composition 상태 추적
const isComposing = useRef(false)

// Rfice :: IME 입력 시작 감지
const handleCompositionStart = () => {
  isComposing.current = true
}
```

**목적**: v6.1.1 fork 이후 어떤 부분이 커스텀인지 명확히 구분하기 위함

### 코드 정리 규칙

**원칙**: 실패한 시도는 즉시 제거합니다.

**예시 시나리오**:

1. A 방법으로 수정 → 테스트 결과 문제 해결 실패
2. B 방법을 시도해야 함 → **A 방법의 모든 코드를 삭제**한 후 B 방법 구현
3. 단, B 방법에서 A의 일부가 실제로 필요한 경우는 유지 가능

**목적**:

- 코드베이스에 실제로 필요한 수정사항만 남기기
- 혼란을 방지하고 유지보수성 향상
